# Changelog

All notable changes to this project will be documented in this file.

## [Unreleased]

### Added
- **Stuck drafts are skipped after 3 tries** (`max_resume_attempts`, `--max-resume-attempts` on `queue` and the main command). Each time an article is translated from a `partial_output/` draft, a counter beside it (`<name>.attempts`) goes up; it is deleted when the article finishes. Backlog pickup (queue mode or an unrelated-draft resume) skips drafts at the limit with a warning naming them, so they no longer eat the `--max-articles` slots. `--title` always attempts the article; `0` removes the limit. Drafts that predate the counter start at 0.
- **Concurrent runs on one machine no longer pick up the same article** (`locks.py`). Processes sharing a queue clone defeated the git-push race check (they commit to the same local repo), retried each other's `partial_output/` drafts, and reclaimed a slow article after `--stale-hours`. Now: a machine-wide flock serialises every queue claim/finish/mark; a per-article flock (under `~/.cache/wiki-translation-harness/locks`, override with `WIKI_HARNESS_LOCK_DIR`) makes `run_pipeline` skip any article another local process is translating (queue, backlog and `--title` alike); claims now read `CLAIMED\t<host>:<pid>:<provider>\t<ts>` and a claim whose process is still alive on this host is never treated as stale. Locks are released by the kernel on exit or crash.
- **`--fresh` on `queue` (and the main command)**: start only articles no agent has begun. In queue mode it skips the local `partial_output/` backlog and passes a new `fresh_only` flag to `queue_lib.claim_next_pending`, so stale `CLAIMED` lines left by another worker are never reclaimed — only a line with no status is claimed. On the main command it is equivalent to `--no-resume`. Default behavior is unchanged (backlog retried, abandoned claims reclaimed).

- **`--title`/`--titles` runs update the shared queue**: after the run, each requested article that has a queue line is marked `DONE` (or `FAILED`) with the engine and review fields, as `queue` mode does, and the change is pushed. A failure never downgrades a `DONE` line or takes a still-pending one off the queue; `--no-mark` skips it and `--queue-repo-dir` points at a different clone (`queue_runner.mark_title_results`, backed by a new per-title `RunStats.article_results`).

- **Progress is shown per article, between the old table and the line-per-section log.** The live view (`progress.py`) is now one row per article: spinner or status icon (`✔` done, `⚠` needs human review, `✖` failed, `○` queued), a bar, `28/42` and a percentage, elapsed time, and the sections in flight (`now: Religion; Cinema (+1)`) or, once every section is in, `assembling, validating, reviewing`. Only the last 4 finished and next 3 queued articles are listed, the rest fold into `… N earlier finished` / `… N more queued`. The worker/section table is gone. The text trail in `logs/run.log` (queue runs) is now a `▶ 'X': starting, 42 sections` line, a progress line about every tenth of the article (`'X': 28/42 sections (66%) · 4m12s · last: Religion | run: …`), and `article 'X' completed in 6m02s (2/10)`, instead of a start and a done line for every section. `ProgressReporter.set_plan` takes an optional `article_chunks` mapping; the pipeline passes it.

### Fixed
- **Hatnotes pointing at pages sqwiki lacks get an `{{ill}}`** (`hatnote_ill.add_ill_to_hatnotes`, run in `post_process_assembled`). `{{Shih}}`/`{{Kryesor}}`/`{{Shiko gjithashtu}}` wrap their parameters in `[[…]]`, so a missing target rendered as a bare redlink (Karl Marx: "Lexo më tepër: Kritika e ekonomisë politike dhe Ekonomia marksiste"). Such a call is now rewritten as `{{Hatnote|Label: {{ill|…}}}}`, with the English titles taken from the source's hatnote of the same kind and number of targets; existing targets in the same call stay plain links. New `MediaWikiClient.existing_pages`.
- **Review findings are repaired with a prompt that allows rewording**: `run_review_pass` fed semantic findings (wrong caption, inconsistent spelling, wrong case) to `repair_chunk`, whose `_REPAIR_FRAME` tells the model it is a syntax-repair backend and to "keep all wording exactly as it is", and which showed only the Albanian chunk. The same findings survived every round (Byzantine Empire: three of three flagged after five rounds). New `repair.repair_chunk_semantic` / `skill_loader.build_semantic_repair_messages` / `_SEMANTIC_REPAIR_FRAME` show the model the source section beside the translation, allow minimal rewording, and tell it to leave a finding alone if it does not apply to that section (findings that cannot be localized are still broadcast to every chunk). A chunk with only structural errors keeps the syntax-only prompt. The frame is part of `SkillContent.content_hash`, so cached repairs from the old prompt are not reused.
- **Model-renamed ref names restored** (`pipeline.restore_ref_names`, run in `post_process_assembled`): the model sometimes rewrites a ref's name (`Brubaker et al-4` -> `Brubaker et-4`) or names a ref the source left unnamed, so several different citations shared one name and Cite reported it as defined multiple times with different content (Cluj-Napoca). Only names the source never uses are touched; each such definition is matched to the source definition with the same URLs and numbers and takes its name (or loses it if the source ref was unnamed).

- **Footnote lists no longer vanish on articles with `{{nlist}}` or `{{efn}}`** (Los Angeles, Julius Caesar, Mount Everest, Washington D.C., Periodic table, all stuck in `needs_human_review` on "references group … not found"). Two causes: (1) enwiki's aliases of `{{notelist}}` (`nlist`, `noteslist`, `notes list`, `note list`, `nls`, `notes`, `efnlist`) don't exist on sqwiki and weren't counted as a note list, so `drop_stray_reference_lists` removed every `<references group="lower-alpha">` the model wrote, the one under "Shënime" included. The source is now rewritten to `{{notelist}}` before chunking (`notes.normalize_notelist_aliases`), the aliases are recognised in the list cleanup, and a note list counts as a `lower-alpha` reflist, so `{{Reflist|group=lower-alpha}}` stands in for it. (2) `{{efn}}` without `|group=` puts its notes in `lower-alpha` and sqwiki's `{{Listë shënimesh}}` lists only that, but the model rewrote the efn as `<ref group="note">` or `<ref group="sh">`; `restore_ref_group_names` now treats `lower-alpha` as a source group when an `{{efn}}`/`{{notelist}}` names none, and maps the invented group back. When a group has more lists than the source, the one directly under a Notes/Shënime heading is kept rather than simply the last.
- `Moduli:TNT/config` is allowlisted as a harmless missing dependency (embedded in sqwiki's own `Div col`, `Refbegin`, `Refend`, `Moduli:Citation/CS1`); it held back Algeria, Imperialism, Nigeria, Pakistan, Propaganda and Sun on a warning alone.

- **`{{R|n=name|r=text}}` definitions become `<ref>` tags before chunking** (`ref_template.expand_r_definitions`). sqwiki's `{{R}}` only reuses a ref (it always emits an empty `<ref name=…/>`), so every reuse of a ref defined that way got "no text was given for refs named X" (Roman Empire: 56 definitions, 54 errors). Calls with several names, a quote or `|loc=` are left alone and logged. Cite-error messages no longer carry the newline that broke the table in `*.review.md`.
- **Two more deterministic ref repairs in `post_process_assembled`** (found on Sun, which now renders with 0 Cite errors from its saved draft): `drop_unsupported_ref_reuses` removes `<ref name="x" />` reuses of a name that neither the source nor the translation defines (the model invented `corona-particle-density`); `collapse_conflicting_ref_definitions` turns the later copies of a definition into reuses, keeping the group, when the source repeats it word for word and the model translated the copies differently (`short`).
- **Fewer `*.review-flags.md` files from the semantic review.** A name or term spelled two ways (Josephus, Jinnah, "open access", Île-de-France; about 10 of the last 58 flagged articles) was sent only to the chunk holding the snippet, whose model could not see the other form and sometimes picked the opposite one. `_consistency_directives` now makes the form used most across the article canonical and tells every chunk using another form to switch. And a review-driven rewrite that leaves a structural error (Religion: one more `}}` than `{{`) no longer ships with a flag: `run_review_pass` restores the last text without one.

### Changed
- **QA is mandatory.** New `qa.py` ports wikiqa's grep-able checks (`grc` in `|language=`, month-only/Albanian-month dates, `{{Shih edhe}}`, wrapped hatnote params, broken `{{transliteration}}`/`{{tlit}}`/`{{native name}}`/`{{cite tweet}}`, `|miniaturë|`, `{{cite web}}` without `|url=`, orphaned `access-date`/`archive-url`, duplicated `{{Sfnmp}}` year params, missing `{{Reflist}}`). They run inside `_validate_assembled`, so assembly and review repair rounds see them, and again as a final gate before save; a failing article is recorded in `needs_human_review` and not saved. `qa_skill_path` can no longer be `null` and a missing wikiqa skill fails the run at startup.

## [0.3.0] - 2026-10-07

### Fixed
- **Review pass no longer undoes post-processing**: after a review-driven repair, `run_review_pass` rebuilt the article with plain `assemble_chunks()`, so the saved file lost every `_post_process` fix (filled `|language=`, sfn renames, restored refs, reference-list repairs). The fixes now live in module-level `pipeline.post_process_assembled`, which both loops call after reassembling, along with comment reconciliation; comments removed during review are added to the report.
- **Reference lists invented at chunk boundaries removed** (`pipeline.py` `_post_process`): when a list-defined `<references>` block is split across chunks, the model ends each later piece with its own `<references />` / `<references group="…"/>`, so every definition after the first chunk falls outside the block. `restore_ref_group_names` maps a translated group name back to the source's (`group="shënim"` → `note`), `drop_stray_reference_lists` keeps only as many renderers per group as the source has, and `extend_references_block_over_trailing_defs` moves `</references>` past the definitions (and model comments) left trailing after it. Albert Einstein: 96 live Cite findings → 6, all of them real dropped citations.
- **Split `<references>` block rejoined**: `pipeline.merge_split_references_blocks` (in `_post_process`) drops the spurious first `</references>` when chunking cut a list-defined `<references>` block in two, which had produced dozens of "no text given" / "not used" Cite errors that per-chunk repair could not fix (Alexander the Great: 58 live findings → 38).
- **Bundled `<ref>{{Sfn}}, {{Sfn}}</ref>` no longer nests refs**: `citation_language.convert_nested_sfn_to_harvnb` renames `{{sfn}}`/`{{sfnp}}` to `{{harvnb}}`/`{{harvp}}` inside any `<ref>`, restoring the source's form (the skill's "bundled harvnb → consecutive Sfn" row made the model swap templates but keep the wrapper). Cleared 15 `FOOTNOTE…` errors on Alexander the Great.
- **New deterministic post-processing fix for a live sq.wikipedia Cite bug**: `citation_language.unwrap_redundant_sfn_ref`, wired into `pipeline.py`'s `_post_process`, strips a redundant `<ref>...</ref>` wrapped directly around a lone `{{sfn}}`/`{{sfnp}}`/`{{sfnm}}` call. `{{sfn}}` already expands to its own `<ref name="FOOTNOTE...">...</ref>` internally, so an extra outer `<ref>` nests one ref inside another — confirmed live against sq.wikipedia (2026-09-22, `Conservatism`) that this corrupts Cite's usage-tracking for the auto-generated name, rendering a live "defined in `<references>` but not used in prior text" error even for that name's only occurrence in the article. The previous behavior (relying on the LLM-based assembly-repair loop) made things worse: since the auto-generated ref name never appears literally in the wikitext, the repair loop couldn't localize the fix to one chunk and broadcast it to all of them, escalating a single cosmetic double-wrap into a genuine "defined multiple times with different content" collision after a few rounds. Only unwraps a *bare* `<ref>` (no `name=`) whose entire content is that one template call — a named ref or one with extra prose alongside is left alone. Does not touch `{{harvnb}}`/`{{harv}}`/`{{harvp}}`, which don't self-wrap and are routinely (correctly) wrapped in an explicit `<ref>` by design.

### Added
- **HTML comments reconciled with the source** (`comments.reconcile_comments`, run per chunk before every assembly in `run_assembly_repair`): comments carried over from enwiki are labelled `<!-- Nga en.wiki: … -->` so sqwiki editors don't read an enwiki editor's note ("don't change without consensus on the talk page") as their own wiki's; comments the model wrote itself are removed and listed in the report under "Model notes removed from the article". Matched in order by relative position and untranslated tokens (URLs, numbers, names, markup). On existing outputs it removed exactly the three model notes (Albert Einstein's repair-loop "Nuk u identifikuan me siguri ndryshimet…", Napoleon's two) and labelled the other 63 comments across eight articles.
- **`{{Cref2}}`/`{{Cnote2}}` expansion before chunking** (`notes.expand_cref_notes`, called from `_plan_article`): each marker becomes a self-contained `<ref name="cnote-x" group="G">note</ref>` (reuse → self-closing ref), the `{{Cnote2 Begin}}…{{Cnote2 End}}` block becomes `{{Reflist|group=G}}`, with G from `|liststyle=` (default `upper-alpha`, which sqwiki renders as letters). Inner `<ref>`s in a note are moved out after it, and `{{sfn}}` in a note becomes `{{harvnb}}`. Previously the marker and its text landed in different chunks and the model dropped markers and left a stray `<ref group>` with no `<references>`.
- **`disable_reasoning` config flag** (default off): sends `reasoning: {"enabled": false}` on OpenRouter calls. Reasoning-by-default models such as `qwen/qwen3.6-27b` otherwise burn the entire output budget on hidden thinking (measured: 9,000/9,000 tokens, zero content, ~255s per call; with it off, the same call finished in 82s), which runs past `request_timeout_s` and retries indefinitely since no `max_tokens` is sent.

### Changed
- **Assembly repairs run in parallel**: a round's chunk repairs now run concurrently, up to `assembly_repair_concurrency` (default 4), instead of one at a time — a 19-chunk round on Albert Einstein took 15 minutes serially.
- `skill_path` now accepts a single directory or a list of directories, to match the upstream skill being split into `enwiki-sqwiki-translation` (translation), `wikiterms`, and `wikiqa`. `skill_loader.load_skill`/`load_skill_cached` concatenate each directory's `SKILL.md` (and, if `include_skill_references` is set, its `references/*.md`) in the given order; reference filenames are namespaced by source skill directory only when more than one path is loaded, so existing single-path configs are unaffected. `config.example.yaml`'s default now lists all three directories.
- **`wikiqa` (the pre-delivery QA checklist) no longer rides along on every normal translation/repair call.** It's now loaded separately via a new `qa_skill_path` config field and appended (`skill_loader.build_repair_messages`'s new `qa_skill` parameter) only to a repair call — the one case where `validate_wikitext` has already found a real defect. `skill_path`'s default dropped `wikiqa`, keeping only `enwiki-sqwiki-translation` + `wikiterms`. Measured against the real skill files: system-prompt tokens on an ordinary translation call drop ~29% (32.4k → 22.9k, tiktoken cl100k_base estimate); a live `claude_code`-provider translation of a real enwiki lead section (Sustainable architecture) showed the same shape live (54.9k → 40.9k input tokens per the CLI's own usage reporting) with both before/after outputs passing static validation and reading as equally fluent, faithful Albanian. `translate_chunk`/`repair_chunk`/`run_assembly_repair`/benchmark mode all thread the new `qa_skill` parameter through; existing single-skill-path configs without `wikiqa` are unaffected.
- **New compact, growing article-level terminology registry** (`VerifiedFacts.established_renderings` in `verification.py`) narrows one remaining cross-section consistency gap: for a source-language term with no confirmed target-wiki sitelink, the first chunk to translate it typically renders it as `{{ill|display|en|Title}}` — that specific rendering is now recorded (first occurrence wins, mechanically parsed from the model's own output, no translation judgment invented by the harness) and surfaced in `build_verified_facts_block` to every later chunk of the same article mentioning the same term ("already rendered elsewhere in this article as ... — reuse that exact rendering"), instead of each chunk independently reinventing its own phrasing. Confirmed against a real model output using this exact pattern (`{{ill|Shtëpia me energji pozitive|en|Energy-plus-house|lt=...}}`).
